## 5. Motion inventory — what the page actually does (codify as MOTION.md)

The skill documents easing/duration tokens; the page has evolved a much richer,
consistent **motion language** that lives nowhere:

**Signature (keep, name, reuse):**
- **Pixel press** — `steps(2)` 70ms, extruded side-face (`--side`) grows on hover, collapses on `:active`. The "old console button" feel. Applies to `.btn`, `.mtab`, `.pbtn`, `.pf-arrow`.
- **Marching pixels** — `repeating-linear-gradient` + `background-position` loop (700ms linear): `.lb-line`, `.gameloop .loop-rail`.
- **Stepped delight** — `steps()` used for character: confetti `steps(5)`, `+1 FRIEND!` `steps(6)`, pet bob `steps(2)`, egg tease `steps(2)`. Rule: *organic pet-world motion is stepped/chunky; UI chrome motion is smooth expo-out.* ← This is the actual (undocumented) law that makes the page feel coherent.
- **Scroll-reactive drift** — marquees driven by scroll velocity + friction (`v += dy*.4; v *= .92; x += v*.18 + idle`), direction-aware sprite flip (`walk-rev`). Used on species strip + review rows.
- **Word-stagger brighten** — spine quote, 80ms/word.
- **Hero choreography** — line masks translateY(110%) → 0, 900ms expo, 70ms stagger; lead/CTA/ship fade-rise at 220/300/380ms; `loaded` class with a **600ms safety timeout** so slow assets never gate the hero. (That timeout is a hard-won trick — document it.)
- **Reveal system** — IO with `-80px` bottom margin, threshold .05, unobserve after fire; `.js`-gated so no-JS sees everything; group children stagger 60ms.
- **Committed-state grammar** — hover invites (lift + coral line) → click commits (coral fill, settled, no line). Already in §2b; extend to new components (po-gallery thumbs use outline instead — unify).
- **Height animation** — `grid-template-rows 0fr→1fr` + `interpolate-size` for accordions (never animate `height`).

**Reduced-motion approach:** page nukes everything to 0.01ms globally. Both skills
say reduced motion = *fewer and gentler, not zero* — keep opacity/color crossfades,
kill movement. Refine the global rule into a two-tier pattern (see §6).

## 6. Principles to adopt (from emil-design-eng + impeccable)

Concrete rules worth writing into the Nowa system, translated to Nowa terms:

1. **The frequency test** (emil): animation budget scales inversely with how often the user sees it. LP hero = rare = full choreography ✓. App UI: tab switches, toggles, list rows are seen 100×/day → minimal or **no** animation. Never animate keyboard-initiated actions. → This becomes the spine of the App-UI motion section.
2. **Duration bands** (both): press feedback 100–160ms · tooltips 125–200 · dropdowns/tabs 150–250 · modals/drawers 200–500 · UI ceiling **300ms** · entrances 500–800 (brand only). Nowa's current values (70ms press, 110/150ms hovers, 700ms reveals) already fit — write the table down so app work inherits it.
3. **Exits ≈ 75% of entrances** (impeccable) and **asymmetric deliberate/press timing** (emil): slow where the user decides, fast where the system responds.
4. **Never `scale(0)`; enter from `scale(.95–.97)` + opacity** (emil). Nowa's translate-based entrances already comply; add the rule for future modals/toasts.
5. **ease-out for enter/exit, ease-in-out for on-screen movement, linear only for constant motion** (emil). Nowa's `--ease-expo` / `--ease-out-strong` are exactly the recommended strong curves ✓ — document the *mapping*, not just the tokens. **Ban bounce/elastic** (impeccable) — and note Nowa's exception: bounce-like life is expressed via `steps()` in the pet world, never via elastic curves.
6. **Transitions over keyframes for anything interruptible/rapid-fire** (emil). Reveals already do this ✓; make it a written rule for toasts/tabs in-app.
7. **`transform-origin` awareness** (emil): popovers/menus scale from their trigger (app UI will need this; marketing page has no popovers yet). Modals stay centered.
8. **Tooltip grammar** (emil): delay first tooltip; adjacent tooltips instant. For the parent app toolbar.
9. **`@starting-style`** for entry animation without JS (emil) — modern replacement for the `loaded`-class pattern where support allows.
10. **clip-path as motion material** (both): Nowa already owns stepped `clip-path` as *shape*; adopting it as *motion* (stepped wipes, dither-style reveals, hold-to-confirm fills) would make the motion language as proprietary as the corners. High-leverage, on-brand.
11. **Blur to mask crossfades** (emil): mission-tab text/video swap could add 2px blur during the 220ms out-phase. Small polish, big perceived quality.
12. **Perf rules** (both): only transform/opacity on hot paths; don't drive per-child CSS vars during drag; Framer-style JS anims drop frames under load → CSS/WAAPI for predetermined motion; `will-change` only while animating; IO unobserve after fire ✓ already.
13. **Perceived performance** (impeccable): <80ms feels instant; optimistic UI for low-stakes app actions (mission toggle), never for payment; skeletons that fade. → App-UI section.
14. **Reduced motion two-tier** (both): keep fades/color, remove movement — instead of the global 0.01ms nuke.
15. **Contrast floors** (impeccable): body ≥4.5:1, large text ≥3:1. Audit candidates on the current page: `--color-mist-body #637381` on parchment at 13–14px (fine print), `.dr-part` 11px cloud-border on ink-charcoal, `.po-tally-sub` at .78 opacity, sage-muted `#4d6b58` on `#e2efdb`. → Add a "minimum ink per background" table to BRAND-RULES (each band token declares its floor text color).
16. **Line-length caps** (impeccable): 65–75ch body, done via `max-width` in `ch` ✓ (already idiomatic on the page — write it down: *every paragraph gets a ch cap*).
17. **Type scale ratio ≥1.25** and **display letter-spacing ≥ -0.04em** (impeccable): Nowa's `-.025em` display tracking ✓; codify.
18. **Semantic z-index scale** (impeccable): see §2.
19. **Button labels verb+object; links meaningful standalone** (impeccable): "Reserve your Nowa" ✓ — cross-reference the content-writing skill so both skills state it once.
20. **No em-dashes** (impeccable): already law in the content skill — note in BRAND-RULES that it applies to UI copy too.
21. **Stagger caps** (both): 30–80ms per item, cap total ≈500ms; Nowa's 60–70ms ✓; never block interaction during stagger.
22. **One hero moment per surface** (impeccable/animate): plan motion as hero + feedback + transition + delight layers, not uniform fade-on-scroll everywhere. See §7.2.

**Explicitly considered and rejected/kept-as-is:**
- impeccable flags cream/parchment body backgrounds as "the saturated AI default of 2026." **Nowa keeps Sunlit cream** — impeccable itself says identity-preservation wins for committed brands; our cream is load-bearing brand identity, paired with a proprietary pixel language. Note it so no future audit "fixes" it.
- emil's `:active { scale(.97) }` press — Nowa's press is the extruded translateY pixel press; it's the branded equivalent. Don't add scale on top.

1. **`.chapter` vs `.geyebrow`.** v2 replaced the pixel chapter marker (coral cell + Tiny5 number) with a plain uppercase eyebrow — which is exactly the pattern impeccable flags as generic AI scaffolding, *and* it dropped the most Nowa-specific part (the pixel number). Options: (a) restore chapter numbers, (b) keep geyebrow but make it distinctly Nowa (Tiny5 group tag? coral cell is already there), (c) keep both with defined roles (chapter = storybook pages, geyebrow = question-group LPs). My take: (b) or (c); pure-uppercase eyebrow on every section is the one generic note on an otherwise proprietary page.
2. **Uniform `.reveal` on ~every section.** Both skills call whole-page fade-on-scroll a tell. The page's *interactive* motion is distinctive; its *entrance* motion is uniform. Consider demoting most section reveals to instant (or opacity-only) and spending the entrance budget on 3–4 earned moments (hero, spine words, gameloop ring, $99 tally).
3. **Two icon languages.** Pixel icons (`.licon`, sprites) vs Feather-style stroke SVGs (deal rows, spec accordions, trust chips, arrows). Probably correct (pixel = pet world, stroke = utility/commerce) — but it's a *rule* today only by accident. Name it: **"Pixel icons for the pet world; 1.8–2.6 stroke line icons for utility. Never mix within a component."**
4. **Sage band status.** `#e2efdb` sage began as a mint-theme leftover and is now the safety/guarantee/founder color across 5 components. Promote to an official band (token + when-to-use) or consolidate to warm-sand?
5. **Logo corner treatment.** Rounded 7px app icon vs stepped-corner world (§3).
6. **`.winbeat`** CSS is orphaned (no markup uses it). Keep as documented component or delete?
